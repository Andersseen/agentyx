# Design critique

Use this after implementing an expressive page and, ideally, after seeing it rendered. The core
question: which parts of this design could I have produced for almost any startup?

## Pass 1: concept test

List the decisions that would survive swapping in a different product. Then check suspicious
defaults: generic gradients or glowing blobs, repeated rounded cards, empty decorative glass, pills
and badges everywhere, a small label above every heading, uniform three-column sections, everything
centered, a highlighted word in the headline, a generic browser mockup, arbitrary monospace,
meaningless arrows, identical fade-up entrances, icon tiles as filler, excess borders and uniform
section rhythm.

None of these are banned. For each, ask whether it belongs to the design concept. If yes, keep it. If
not, replace it with something drawn from the product, or simplify it away.

## Pass 2: craft test

Look for hierarchy that is flat or competing, density that is excessive or too sparse, weak
transitions between sections, type that does not hold at narrow widths, composition that only
stacks on mobile, decoration with no job and drift from the established brand or design system.

## Pass 3: floor test

Confirm focus visibility, contrast, keyboard use, semantic structure, reduced motion, overflow and
performance. Expression never overrides these.

## Act

Rank findings by impact. Fix the ones that matter in one batch, then confirm once. Record what you
kept on purpose and why, so the next reviewer does not reopen it.

## Boundaries

Critique the work, not personal taste. Tie each finding to the concept, the audience or a concrete
defect. Do not iterate on pixels indefinitely: one critique, one batch of fixes, one confirmation.

## Stop condition

Stop when remaining differences are preference rather than defects. State honestly whether rendered
review took place; if it did not, say that it was not performed.
