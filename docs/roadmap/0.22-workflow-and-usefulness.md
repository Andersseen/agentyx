# 0.22 — Make the everyday harness easier to choose and assess

This minor improves the existing project-local setup flow. It does not close the separate real-agent
evaluation or three-pilot release gates required for 1.0.

## R220-01 — Make common setup and observation legible

Delivered in this change:

- Interactive init identifies the existing `technical` pack as the common engineering base. Stack
  recommendations stay editable; workflow packs and optional capabilities are still opt-in.
- Init explains project-local reuse and the observation path without adding config fields or changing
  JSON output.
- Doctor explains when supported providers have no observer hooks, when selected hooks are waiting
  for installation, and when fresh sessions are needed for the installed baseline.
- Skills describe when planning and verification are useful, with proportional guidance for small
  changes.
- Claude hooks use the documented shell form so Windows does not try to spawn npm's `.cmd` shim as
  an executable. A render test proves output shape, not provider runtime activation.

Acceptance: the interactive base is recognizable, MCP remains opt-in, init and Doctor distinguish
configuration from activity observation, and hook output preserves ownership markers and unrelated
provider settings. JSON contracts remain unchanged.

## R220-02 — Extend reproducible behavior evaluation

Delivered in this change:

- Bumped the measured benchmark definition to version 2 without changing version 1's six fixtures or
  the recorded Codex preflight.
- Added a project-context and verification task. Its Agentyx treatment gets a configured command and
  constraints through the existing generated project-context Skill; baseline retains the same
  package scripts and repository instructions.
- Expanded the deterministic two-provider, three-repetition plan from 72 to 84 runs. Validation
  still runs no providers and does not claim quality improvement.
- Added a project-pilot protocol for TypeScript, Angular, and a TypeScript monorepo. All pilots stay
  pending until humans execute and record them.

Acceptance: benchmark validation catches malformed treatment context and initial fixture state;
preflight evidence is preserved; external trials are clearly pending where provider access is absent.

Verification: `pnpm check`, built CLI acceptance checks, `pnpm eval:skills`, `pnpm eval:behavior`,
`pnpm smoke:pack`, and a scratch lifecycle including selection adjustment, sync and uninstall.

Release status: implementation and deterministic checks may ship in the next minor. 1.0 remains
blocked on full real-provider behavior evaluation and all three real-project pilots.
