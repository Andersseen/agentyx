# Project report minor

Status: implemented. Written against packages at 0.20.0; the next release version is chosen by
Changesets, not by this document.

## Why this was pulled ahead of R100

R100-03 (second-provider evidence) is blocked by external provider availability: only Codex has run
the benchmark, and it tied the baseline. R100-04 (pilots) waits behind it, and 1.0 waits behind both.
Rather than idle, development moved to a user-visible feature that does not touch the evidence gate:
`agentyx report`, a deterministic, self-contained HTML view of the project's harness.

This does not complete, replace or weaken R100. The report is observational and says nothing about
whether Agentyx improves agent behavior.

## Scope

- `agentyx report [--output <path>] [--overwrite]`, default `agentyx-report.html`.
- Read-only apart from the requested file; project-relative `.html` path only.
- One CLI-internal `ReportModel` composed from existing domain results (Doctor's builder, the
  resolution explanation, the lock, the project graph). No new health, provenance or lock logic.
- Rendered by a Flowview template compiled at build time; the CLI ships only `@flowview/runtime`.
- Out of scope: `--open`, other formats, servers, dashboards, report diffing or history, live data,
  R100 results in the report.

See [docs/report.md](../report.md) for behavior and limits.
