# 0.8 — Project Context & Project Graph

Prerequisite: current 0.7.0 source baseline inspected. The 0.7 roadmap tasks are not recorded as
complete and their proposed explain/exclusion/readiness features are absent from source; this 0.8
work uses only the existing project loader, resolver, installer, and manifest lifecycle.

## Product outcome

Project Context tells an agent how this repository works. Project Graph tells it where this
repository fits in the system. Both are explicit, local, provider-neutral facts in `.agentyx.json`.
The graph describes semantic relationships and architectural ownership, never the npm dependency
tree. Repository/docs/MCP fields are resource references only; 0.8 does not fetch, clone, index, or
query them.

```json
{
  "project": {
    "id": "web",
    "name": "Web",
    "owns": ["frontend"]
  },
  "relations": [
    {
      "id": "api",
      "name": "API",
      "type": "consumes",
      "role": "backend-api",
      "repository": "https://github.com/acme/api",
      "owns": ["backend-api"]
    }
  ],
  "context": {
    "commands": { "verify": { "command": "pnpm check", "cwd": "." } },
    "areas": [{ "path": "packages/core", "purpose": "Provider-neutral domain logic." }],
    "constraints": ["Keep terminal output outside packages/core."]
  }
}
```

## Domain and projections

Zod schemas own validation for project identity, direct relations (`uses`, `integrates`, `consumes`,
`extends`), role, resource references, ownership, and optional internal context. A single graph model
feeds terminal text, deterministic JSON, Mermaid, SVG, and the generated Skill. The SVG renderer is
a dependency-free, deterministic center-and-spokes layout with a distinct current-project node,
arrowed edges, relation labels, XML escaping, and truncated long labels.

The generated `agentyx-project-context` Skill contains concise usage rules and JSON-encoded project
facts. It is installed through existing adapters, manifests, conflict handling and prune behavior.
No provider gets a provider-specific copy. Context paths are project-relative, checked for existence
and symlink containment, and commands are instruction data that are never executed.

## CLI

```sh
agentyx graph
agentyx graph --json
agentyx graph --format mermaid
agentyx graph --format svg --output docs/project-graph.svg
agentyx graph show api
agentyx graph owner backend-api
```

The SVG output path is explicit, project-relative, and created only if absent. The command does not
create parent directories or overwrite files.

## Implementation tasks

- **R080-01 — Model project facts:** extend `.agentyx.json` with project identity, direct relations,
  ownership, and internal context; validate identifiers, relation types, references, duplicate
  entries, and project-relative context paths.
- **R080-02 — Share one canonical context:** render context and graph facts into one provider-neutral
  Skill and route it through resolution, adapters, manifests, update, prune, and conflict handling.
- **R080-03 — Complete the user workflow:** expose text/JSON/Mermaid/SVG projections and `show`/`owner`
  queries, add conservative opt-in command suggestions during interactive `init`, then document,
  package, and demonstrate the feature outside the checkout.

The initial release does not infer project identity during `init` or infer relationships from local
package dependencies. Developers author graph facts explicitly; initialization never invents edges.
Interactive initialization may offer existing `check`, `test`, `build`, and `lint` scripts only
when it has an unambiguous package manager. Choices begin empty, selected commands are literal
instruction data, and non-interactive init creates no context automatically.

## Progression

- 0.8: Understand this repository and its direct architectural relationships.
- 0.9: Make that configured environment reproducible.
- 0.10: Validate provider compatibility and usefulness.
- 1.0: Publish a stable compatibility contract.

After 1.0, possible directions include multi-repo graph composition, automatic relation candidate
discovery, an Agentyx Context MCP, task-aware context resolution, an interactive graph explorer, and
impact analysis. These are future notes, not part of 0.8.
